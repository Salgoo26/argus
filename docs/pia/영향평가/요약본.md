# 개인정보 영향평가 요약본

> 안내서 요약본 작성방법(6.2, 75~77쪽) 양식에 따라 작성했습니다. 영향평가서 본문은 각 단계 산출물로 대신합니다
> 공개용 문서이므로 시스템 구조, 접근통제 방식, 암호화 세부사항은 적지 않습니다

## 1. 평가대상시스템 개요

| 구분 | 내용 |
|---|---|
| 대상기관 | 커머스 플랫폼(가상의 민간 사업자) |
| 평가기관 | 자체 평가(외부 평가기관 입장에서 수행) |
| 평가기간 | 2026.10.19 ~ 2026.11.28 |
| 평가예산 | 해당 없음(자체 평가) |
| 시스템명 | 커머스 쇼핑몰·백오피스 |
| 시스템 구축 일정 | 2026.09 ~ 2026.10(개발 완료, 운영 오픈 전) |
| 추진개요 및 목적 | 회원가입부터 주문·배송·취소·환불·문의·탈퇴까지 고객 거래를 처리하는 온라인 쇼핑몰과, 이를 운영하는 백오피스를 새로 구축 |
| 추진성격 대상여부 | 시행령 제35조의 영향평가 의무 대상이 아닌 민간 사업자로, 개인정보 보호법 제33조제11항에 따라 자율적으로 평가 |
| 추진주체 | IT팀 |
| 추진유형 | 신규 구축. 개발을 마치고 운영 오픈 전인 시스템을 설계 문서와 개발 환경 화면으로 평가했고, 운영 배포에 해당하는 사항(전송 암호화·접근통제 등)은 배포 설계안을 기준으로 판단 |
| 주요내용 | 고객은 쇼핑몰에서 회원가입·본인확인, 주문·결제, 배송 조회, 취소·반품, 1:1 문의를 이용합니다. 내부 취급자는 백오피스에서 회원·주문·배송·환불·문의를 처리합니다. 결제는 PG사, 배송은 택배사에 맡기고, 본인확인은 본인확인 기관을 이용합니다 |

## 3. 개인정보 처리 흐름분석

개인정보를 처리하는 업무 8개(회원관리, 주문·결제, 배송, 취소·반품·환불, 고객 상담, 마케팅, 계정·권한 관리, 접속기록 관리)를 도출하고, 업무마다 수집부터 파기까지의 흐름을 분석했습니다.

| 단계 | 처리 내용 |
|---|---|
| 수집 | 고객이 쇼핑몰에 직접 입력하거나, 본인확인 기관과 PG사에서 처리 결과로 받음 |
| 보유·이용 | 내부 취급자가 백오피스 화면이나 DB 직접접근으로 처리하고, 처리 내역은 접속기록으로 남겨 점검 |
| 제공·위탁 | 제3자 제공은 없고, 결제는 PG사·배송은 택배사에 위탁해 업무에 필요한 항목만 제공 |
| 파기 | 회원 탈퇴 시 회원정보를 즉각적으로 파기하고, 전자상거래법에 따라 보존할 거래 기록만 분리 보관 |

### 5.1 관련 법령 준수 여부에 대한 분석·평가

| 처리 단계 | 준수 사항 | 미흡 사항 |
|---|---|---|
| 수집 | - 회원·주문·환불·문의 정보는 개인정보 보호법 제15조제1항에 따라 동의나 계약 이행을 근거로 수집하고, 동의를 받을 때 목적·항목·보유 기간·거부 권리를 알림<br>- 주민등록번호 없이 휴대폰 본인확인으로 가입하게 해 제24조의2를 지킴<br>- 동의를 항목별로 받고, 선택 항목에 동의하지 않아도 가입할 수 있음(제22조제1항·제5항) | - 저장하는 본인확인 결과(CI·DI·생년월일 등)에 수집 근거가 없고, 처리 목적이 없는 항목까지 보관함(제15조, 제16조)<br>- 마케팅 동의에서 홍보 연락 사실과 보유 기간이 눈에 띄게 표시되지 않음(제22조제2항) |
| 보유·이용 | - 회원정보는 탈퇴·동의 철회 시까지, 거래·분쟁 기록은 전자상거래법 시행령 제6조제1항에 따라 5년·3년 보유함 | - 거래 기록 보유기간을 거래 시점이 아닌 탈퇴 시점부터 세어 법정 기간보다 오래 보관할 수 있음(제21조제1항)<br>- 마케팅 발송 때 수신 동의를 확인하지 않고, 마케팅 분석에 별도 동의 없이 회원·주문정보를 씀(제18조제1항, 정보통신망법 제50조제1항) |
| 제공·위탁 | - 제3자 제공은 없고, 결제대행사(PG) 위탁 사실을 처리방침에 공개함 | - 택배사와 본인확인 기관에 맡긴 업무는 공개하지 않음(제26조제2항) |
| 파기 | - 회원 탈퇴 시 회원정보를 즉각적으로 파기하고, 법정 보존 기록은 별도 보존 테이블에 분리해 보관함(제21조제1항·제3항) | - 보존 기간이 지난 분리보관 기록·접속기록·권한 이력을 파기하는 절차가 시스템에 반영되지 않음(제21조제1항)<br>- 별도 보존 테이블에 운영 테이블과 같은 권한으로 접근할 수 있음(제21조제3항) |
| 안전조치·권리 보장 | - 비밀번호와 환불계좌번호를 암호화해 저장하고(안전성 확보조치 기준 제7조), 취급자마다 개별 계정을 주고 접속기록을 남김(제5조, 제8조)<br>- 처리방침에 법정 기재 사항과 침해 신고 방법을 안내함(제30조제1항) | - 내부 관리계획이 없음(제29조, 안전성 확보조치 기준 제4조)<br>- 권리 요구를 처리하는 절차와 거절 시 이의제기 방법이 없음(제35조~제38조)<br>- 처리방침에 일부 처리 항목과 목적이 빠져 있고, 이전 버전을 볼 수 없음(제30조) |

### 5.2 개인정보 처리, 개인정보처리시스템 운영관리 및 기술적 조치사항에 따른 분석·평가

| 구분 | 보호조치 현황 | 위험요소 |
|---|---|---|
| 개인정보 처리 | 주민등록번호와 카드번호를 받지 않고, 탈퇴 시 회원정보를 즉각적으로 파기함 | 마케팅 추출 때 수신 동의를 확인하지 않아, 동의하지 않은 회원에게 광고가 갈 수 있음 |
| 계정·권한 관리 | 취급자별 개별 계정과 역할별 접근 범위가 있고, 권한 이력을 3년 보관함 | 인사 변동과 권한 승인 절차가 없고, DB 직접접근이 IT팀 밖까지 열려 있음 |
| 접근통제·인증 | 관리자 경로는 허용한 IP에서만 접속하고, 인증 5회 실패 시 잠금·30분 미사용 시 재인증을 적용함 | 쇼핑몰에 들어오는 웹 공격을 탐지·차단할 수단이 없고, DB 직접접근과 외부 접속에 추가 인증이 없음 |
| 암호화 | 비밀번호와 환불계좌번호를 암호화해 저장하고, 인증정보는 암호화 구간으로만 주고받음 | 내려받은 회원 파일과 PG사·택배사 연계 구간이 암호화되지 않음 |
| 접속기록 | 화면 경유와 DB 직접접근을 모두 기록하고, 위·변조를 막으며 이상행위를 자동 탐지함 | 보관 기간을 정하지 않았고 백업을 같은 서버에만 둠. 서버에 직접 접속하는 경로는 기록이 남지 않음 |
| 악성프로그램·취약점 | 취급자 PC에 백신을 쓰고, 라이브러리 보안 업데이트를 자동 알림으로 확인함 | 서버 백신, 운영체제 보안 업데이트, 정기 취약점 진단 절차가 없음 |
| 출력·화면 | 배송 목록, 카드번호, 환불계좌번호는 마스킹해 보여 줌 | 회원·주문 화면과 회원 CSV에 업무에 필요 없는 항목까지 그대로 나옴 |

## 6. 위험요인에 대한 개선조치

부분이행·미이행 33개 지표에서 침해요인을 도출해 위험도를 산정했고(최고 14점 6개), 이를 개선과제 15개로 묶어 개선계획을 세웠습니다. 시기별로는 단기(2027.03) 9개, 중기(2027.06) 5개, 장기(2027.12) 1개입니다.

### 6.1 주요 위험요소에 따른 개선조치 방안

| 구분 | 주요 위험요소 | 개선조치 방안 | 시기 |
|---|---|---|---|
| 개인정보 처리 | 본인확인 결과에 수집 근거가 없고, 목적 없는 항목까지 보관 | 계약 이행에 필요한 항목은 회원가입 화면에 안내하고, 쓰지 않는 DI·성별·통신사 등은 저장을 멈추고 삭제 | 단기 |
| | 보존 기간이 지난 기록이 남아 있음 | 보존 기간이 지난 분리보관 기록·접속기록·권한 이력을 매일 자동 파기하고 파기 관리대장 작성 | 단기 |
| | 수신에 동의하지 않은 회원에게 광고가 갈 수 있음 | 발송할 때 수신 동의 회원만 추출하고, 매체별 수신 동의와 분석 이용 동의를 따로 받음 | 단기 |
| 계정·권한 관리 | 인사 변동·권한 승인 절차가 없고, DB 직접접근 범위가 넓음 | 인사 변동 당일 권한 변경·말소, 권한은 신청 → 부서장 승인 → IT팀 부여 순으로 처리, DB 직접접근은 IT팀만 | 단기·중기 |
| 접근통제·인증 | 웹 공격 탐지 수단이 없고, DB 직접접근·외부 접속에 추가 인증이 없음 | 웹 방화벽 도입과 연 1회 이상 웹 취약점 진단, DB 직접접근과 외부 접속에 OTP·VPN 적용 | 단기·중기 |
| 암호화 | 내려받은 회원 파일과 연계 구간이 암호화되지 않음 | 회원 CSV는 비밀번호를 건 압축 파일로만 내려받고, PG사·택배사 연계 구간에 TLS 1.2 이상 적용 | 중기 |
| 접속기록 | 보관 기간이 없고 백업이 같은 서버에 있으며, 서버 직접 접속이 기록되지 않음 | 2년 이상 보관, 별도 저장소에 백업, 서버 접속은 접근통제 서버를 거치도록 일원화 | 중기·장기 |
| 악성프로그램·취약점 | 서버 백신과 운영체제 보안 업데이트 절차가 없음 | 서버 백신을 설치해 매일 검사하고, 운영체제 보안 공지를 주 1회 확인해 적용 | 단기 |
| 출력·화면 | 업무에 필요 없는 항목까지 그대로 출력됨 | 부서·용도별로 출력 항목을 줄이고, 회원·주문 화면은 마스킹하되 전체 보기는 기록을 남김 | 중기 |
| 관리체계 | 내부 관리계획과 권리 요구 처리 절차가 없음 | 접속기록 점검 주기·방법을 담은 내부 관리계획을 수립·시행하고, 권리 요구 처리 절차와 이의제기 안내 마련 | 단기 |

### 6.2 위험요소에 따른 정보주체 인지사항

**정보주체가 인지해야 할 위험요소와 이를 제거하기 위한 노력**

| 위험요소 | 위험요소를 제거하기 위한 노력 |
|---|---|
| 쇼핑몰을 노린 해킹으로 회원정보가 유출될 수 있음 | 웹 공격을 탐지·차단하는 수단을 갖추고, 매년 취약점을 진단해 조치합니다 |
| 내부 취급자가 업무와 관계없이 개인정보를 열람하거나 반출할 수 있음 | 업무에 필요한 사람에게만 권한을 주고, 처리 기록을 정기적으로 점검하며, 내려받는 파일은 암호화합니다 |
| 수신에 동의하지 않은 광고를 받을 수 있음 | 발송할 때마다 수신 동의 여부를 확인해 동의한 회원에게만 보냅니다 |
| 보유 기간이 지난 개인정보가 남아 있을 수 있음 | 보존 기간이 지난 정보는 매일 자동으로 파기하고 파기 기록을 관리합니다 |

**정보주체의 개인정보 보호조치와 알아야 할 사항**

| 구분 | 내용 |
|---|---|
| 보호조치 | - 주민등록번호를 받지 않으며, 카드번호는 결제대행사 결제창에서만 입력해 쇼핑몰에 저장하지 않습니다<br>- 비밀번호와 환불계좌번호는 암호화해 저장하고, 로그인에 여러 번 실패하면 계정을 잠시 잠급니다<br>- 내부 취급자가 개인정보를 처리한 기록을 남기고 정기적으로 점검합니다 |
| 알아야 할 사항 | - 결제는 결제대행사, 배송은 택배사, 본인확인은 본인확인 기관이 맡아 처리하며, 필요한 항목만 제공합니다<br>- 열람·정정·삭제·처리정지는 마이페이지나 고충 처리 부서에 요구할 수 있고, 처리 결과에 이의를 제기할 수 있습니다<br>- 회원 탈퇴 시 회원정보는 즉각적으로 파기되고, 거래 기록은 법령에서 정한 기간 동안만 분리 보관한 뒤 파기됩니다<br>- 다른 사이트와 같은 비밀번호를 쓰지 말고, 쇼핑몰·택배사를 사칭해 비밀번호나 결제 정보를 묻는 연락에는 응하지 마세요<br>- 개인정보 침해가 의심되면 개인정보침해신고센터나 개인정보분쟁조정위원회에 신고·상담할 수 있습니다 |

## 7. 평가결과

대상 시스템은 주민등록번호를 받지 않고, 동의를 항목별로 받으며, 비밀번호와 계좌번호를 암호화하고, 취급자별 계정과 접속기록 점검을 갖추는 등 개인정보 처리의 기본 보호조치는 마련되어 있습니다. 반면 수집 근거 정리, 보존 기간이 지난 정보의 파기, 웹 공격 대응과 취약점 관리, 내부 관리계획처럼 법령이 요구하는 관리 절차는 시스템과 문서에 충분히 반영되지 않았습니다.

법령상 의무에 해당하거나 침해사고로 즉각 이어질 수 있는 과제 9개는 2027년 3월까지 우선 이행하고, 나머지 과제는 계획한 시기에 맞춰 진행해야 합니다. 이행 결과는 서비스 오픈 전후 이행점검에서 확인합니다.
