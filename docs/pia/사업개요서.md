# 사업개요서 — 데모 커머스

> 기준: 개인정보 영향평가 수행안내서(2025.10) 2.3절(34쪽). 사업 배경·목표·개요와 개인정보 처리의 법적 근거를 정리합니다

---

## 1. 사업 개요

| 항목 | 내용 |
|---|---|
| 사업명 | 데모 커머스(쇼핑몰·백오피스) 구축 |
| 성격 | 신규 구축, 운영 오픈 전. 민간 사업자, 공공시스템 아님 |
| 추진 배경 | 접속기록 점검 서비스 ARGUS가 감시할 대상 개인정보처리시스템으로 만들었습니다. 회원가입·동의, 주문·결제, 배송지, 환불계좌, 1:1 문의, 탈퇴·파기까지 개인정보 처리 흐름이 다양하고 범위가 명확해서 커머스를 골랐습니다(`docs/requirements.md` 1-1) |
| 목표 | 고객의 회원가입부터 주문·배송·취소·문의·탈퇴까지 처리하고, 직원(개인정보취급자)이 관리자 화면과 DB 직접접근으로 고객 정보를 처리하는 업무를 갖춥니다 |
| 주요 기능 | 회원가입(아이디·이메일 인증·휴대폰 본인확인), 주문·결제(카드는 PG 결제창, 무통장입금은 관리자 입금 확인), 배송(택배사 연동), 취소·청약철회·환불(카드 승인 취소 또는 계좌 이체), 1:1 문의, 마케팅 수신 동의, 탈퇴·분리보관 |
| 예상 규모 | 향후 1년 정보주체 10만 명 |
| 운영 환경 | 로컬 Docker Compose. 운영 배포는 설계만 있습니다(`docs/architecture.md` 7-2). 현재 데이터(시드) 건수는 **확인 필요** |

## 2. 시스템 구성

| 구분 | 구성요소 | 역할 |
|---|---|---|
| 평가 대상 | platform-web | 고객 화면(`/`, 쇼핑몰)과 관리자 화면(`/admin`, 백오피스). URL 경로로 나뉩니다 |
| 평가 대상 | platform-api | 고객·관리자 API. 관리자 행위의 접속기록 생성. PG·택배와 서버 간 연동 |
| 평가 대상 | platform-db | PostgreSQL. 회원·본인확인 결과·동의·배송지·환불계좌·주문·결제·배송·취소/반품·문의·취급자 계정·분리보관 기록 |
| 평가 대상 | db-gateway | 취급자가 DB 툴로 platform-db에 직접 접속하는 경로. 개인 토큰으로 인증하고 실행한 SQL과 결과의 회원번호를 기록 |
| 연계 (평가 제외) | platform-relay | 접속기록을 ARGUS로 전송(outbox) |
| 연계 (평가 제외) | ARGUS | 접속기록 수집·이상행위 탐지·소명·보고 |
| 연계·수탁자 (평가 제외) | 가상 PG(데모페이) | 별도 서비스·자체 DB. 결제창(카드번호는 PG만 받음), 승인·조회·취소 API, 영수증 |
| 연계·수탁자 (평가 제외) | 가상 택배(데모택배) | 별도 서비스·자체 DB. 배송 접수·반품 회수·조회·접수 취소 API, 상태가 바뀌면 쇼핑몰에 통지 |
| 연계 (평가 제외) | 가상 본인확인 창 | 통신사·이름·주민번호 앞 7자리·휴대폰을 받아 본인확인 결과를 돌려줍니다. 주민번호는 창 밖으로 보내지 않습니다. 통신사의 별도 서비스 |

PG·택배는 커머스와 분리된 외부 시스템이고 ARGUS 감시 대상이 아닙니다.

## 3. 정보주체와 개인정보취급자

| 구분 | 내용 |
|---|---|
| 정보주체 | 쇼핑몰 회원, 배송지 받는 사람, 무통장입금 입금자(입금자명, 기본값은 회원 이름) |

| 처리하지 않는 정보 | 주민등록번호(본인확인 창 안에서만 입력), 민감정보, 전체 카드번호(PG만 받고 쇼핑몰은 마스킹 번호만 받음) |

## 4. 처리 업무와 법적 근거

### 4-1. 처리방침 v3 기준 (현행 그대로)

출처: 개인정보 처리방침 v3 2·3절, `docs/policy.md`, `docs/db-schema.md`.

| 처리 업무 | 항목 | 법적 근거(처리방침 표기) | 보유 기간 |
|---|---|---|---|
| 회원 가입·관리 | 이메일(아이디), 비밀번호(일방향 암호화), 이름, 휴대전화번호 | 동의(제15조제1항제1호, 필수) | 탈퇴 시 즉시 파기 |
| 연령 확인 | 만 14세 이상 여부(체크박스) | 가입 시 확인(제22조의2) | 탈퇴 시 즉시 파기 |
| 배송지 관리 | 배송지 이름, 받는 사람, 휴대전화번호, 우편번호, 주소, 상세주소 | 동의(제15조제1항제1호, 필수) | 탈퇴 시 즉시 파기 |
| 주문·결제 | 주문 상품·금액·일시, 배송 정보(배송지 사본), 결제 결과(카드사, PG 거래번호, 승인 일시) | 동의(제15조제1항제1호, 필수) | 탈퇴 후 분리보관 5년(전자상거래법 시행령 제6조제1항제3호) |
| 환불계좌 | 은행, 예금주, 계좌번호(AES-256-GCM 암호화) | 동의(제15조제1항제1호, 필수) | 탈퇴 시 즉시 파기 |
| 1:1 문의 | 문의 제목·내용, 답변 | 동의(제15조제1항제1호, 필수) | 탈퇴 후 분리보관 3년(같은 항 제4호) |
| 마케팅 정보 수신 | 이메일, 이름 | 동의(제15조제1항제1호, 선택) | 동의 철회 또는 탈퇴 시까지 |
| 동의 이력 | 동의 항목·버전, 동의·철회 일시, 접속 IP | 동의 사실의 입증(제22조) | 탈퇴 시 즉시 파기 |
| 취급자 접속기록 | 처리한 회원번호 | 법령상 의무(제29조, 안전성 확보조치 기준 제8조) | 최소 1년(ARGUS 보관) |

- 처리방침 1절의 처리 목적에는 주문 처리(주문·결제·배송·환불, 배송 연락)와 마케팅(이벤트·혜택 안내 이메일 발송)이 있습니다.
- 처리방침 5~7절: 제3자 제공 없음, 위탁은 데모페이(PG) 1곳, 국외 이전 없음.
- 정책정의서는 계약 이행에 필요한 항목은 동의 없이도 처리할 수 있으나(제15조제1항제4호) 동의를 받는 방식을 택했다고 적고 있습니다(`docs/policy.md` 4-3, 10/11 유지 결정).

### 4-2. 기능 확장으로 생긴 처리

처리방침은 기능 확장 후 개정되지 않았습니다. 아래 "처리방침 표기" 칸은 v3에 해당 내용이 있는지만 적습니다.

| 처리 업무 | 새로 처리하는 항목 | 보유·파기(설계) | 처리방침 표기 |
|---|---|---|---|
| 회원 가입·본인확인 | 아이디(로그인용, 이메일과 별도), 이메일 인증 시각, 본인확인 결과(CI·DI·이름·생년월일·성별·내외국인·휴대폰·통신사·본인확인 시각) | 회원 정보와 같음 | 없음 |
| 카드 결제 | PG로 전달: 주문번호·주문명·금액·구매자 이름·이메일·휴대폰. PG에서 받아 저장: 마스킹 카드번호(앞 6·뒤 4자리)·승인번호·할부·영수증 주소 | 주문·결제와 같음 | PG 위탁은 있음, 전달 항목은 없음 |
| 무통장입금 | 입금자명, 주문 시점 입금 계좌 사본, 입금 기한, 입금 확인 시각·처리자 | 분리보관 때 입금자명은 "(분리보관)" | 없음 |
| 배송 | 배송 메모(주문 시 입력), 택배 접수번호·송장번호·택배 상태. 택배사로 전달: 받는 사람 이름·연락처·우편번호·주소·상세주소·배송 메모·상품명·수량·주문번호·보내는 곳 | 탈퇴 시 송장번호는 분리보관 | 배송 목적은 있음, 택배사 위탁은 없음 |
| 취소·청약철회·환불 | 취소·반품 사유·상세, 환불액, 취소 거래번호, 회수 접수번호·회수 송장번호, 환불 방식, 이체 계좌 사본(은행·예금주·계좌번호 암호문·끝 4자리), 이체 완료 시각·처리자, 주문 상태 이력(처리자) | 탈퇴 시 취소·반품 기록은 분리보관, 운영 테이블의 사유 상세는 비움. 분리보관 때 이체 계좌 사본은 삭제 | 환불 목적은 있음, 항목은 없음 |
| 환불계좌 | 회원당 1개 → 최대 5개 | 회원 정보와 같음 | 있음(4-1) |

## 5. 외부 연계

| 연계 대상 | 방향 | 넘어가는 정보 | 근거 문서 |
|---|---|---|---|
| 가상 PG(데모페이) | 쇼핑몰 → PG | 결제창 요청: 주문번호·주문명·금액·구매자 이름·이메일·휴대폰. 승인·취소 요청: paymentKey·주문번호·금액·사유 | 커머스 확장 구현 문서 |
| 가상 PG | PG → 쇼핑몰 | 승인 결과: 카드사·마스킹 카드번호·승인번호·할부·승인 시각·영수증 주소 | 같음 |
| 가상 택배(데모택배) | 쇼핑몰 → 택배 | 배송 접수: 받는 사람 이름·연락처·우편번호·주소·상세주소·배송 메모·상품명·수량·주문번호·보내는 곳. 반품 회수 접수 | 커머스 확장 구현 문서 |
| 가상 택배 | 택배 → 쇼핑몰 | 상태 통지(서명): 접수번호·송장번호·상태 | 커머스 확장 구현 문서 |
| 가상 본인확인 창 | 본인확인 → 쇼핑몰 | 본인확인 결과(서명 토큰, 30분) | 커머스 확장 구현 문서 |
| ARGUS | 플랫폼 → ARGUS | 취급자 접속기록(계정, 일시, 접속지, 수행업무, 처리한 회원번호) | `docs/api-spec.md` 시스템 간 API, `docs/architecture.md` |
| DB 게이트웨이 → ARGUS | 게이트웨이 → ARGUS | DB 직접접근 접속기록(SQL, 결과의 회원번호) | 같음 |

## 6. 이후 단계에서 쓰는 방법

③ 흐름분석에서 4절의 처리 업무를 출발점으로 처리업무표와 영향도 등급을 만듭니다. 4절의 법적 근거가 적정한지, 처리 목적과 실제 처리가 맞는지는 ④ 침해요인 분석의 3영역에서 판단합니다.
