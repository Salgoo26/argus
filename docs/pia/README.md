# 개인정보 영향평가(PIA)

> 커머스 플랫폼(쇼핑몰·백오피스)을 대상으로 개인정보보호위원회「개인정보 영향평가 수행안내서」(2025.10)의 수행 단계를 따라 진행 중인 자체 영향평가입니다.
> 최종 갱신: 2026-11-27

## 평가 개요

| 항목 | 내용 |
|---|---|
| 평가 대상 | 쇼핑몰(고객 화면), 백오피스(관리자 화면), platform-api, platform-db, DB 직접접근 통제 |
| 연계 시스템 (평가 제외) | ARGUS, 가상 PG(결제 위탁), 가상 택배(배송 위탁), 가상 본인확인 창. 흐름도·구조도에 표시하고, 넘겨주는 항목과 위탁 관리만 평가 |
| 평가 기준 | 수행안내서(2025.10) 5개 영역·28개 분야·121개 지표. 3영역(처리단계별 보호조치)·4영역(기술적 보호조치) 중심, 판단할 수 없는 항목은 "해당 없음 + 사유"로 기재 |
| 평가 시기 | 구축을 마치고 운영 중인 시스템을 대상으로, 전반적인 개인정보 보호체계를 점검·개선하기 위해 수행하는 평가입니다(수행안내서 4.2 "기 구축되어 운영 중인 시스템의 경우"). 신규 구축 시 설계 완료 전에 수행하는 사전 평가(4.1)가 아니므로, 개선계획은 설계 반영이 아닌 운영 중 보완으로 이행합니다 |
| 수행 방식 | 외부 평가기관 입장에서 평가자료(설계 문서·처리방침·화면)를 분석하고, 코드·DB 확인이 필요한 부분은 시스템 담당자 인터뷰·실사로 확인 |
| 한계 | 시스템 개발자와 평가자가 같아 독립성이 없으며, 지정 영향평가기관의 정식 평가가 아닌 안내서 방법론에 따른 자체 평가 |

## 1. 영향평가 수행계획 수립

### 1.1 영향평가 수행계획 수립

평가 목적, 대상과 범위, 평가 주체, 기간, 절차, 평가기준과 평가항목, 자료수집·분석 계획, 결과 정리, 품질관리 방안을 정했습니다. 1인 자체 평가이므로 사전준비 단계(필요성 검토·대가 산정·평가기관 선정)는 생략했습니다.

- 산출물: [영향평가 수행계획서](영향평가_수행계획서.md)

### 1.2 ~ 1.4 영향평가팀 구성·역할 정의·운영계획 수립

1인 자체 평가이므로 평가 수행자 1명과 시스템 담당자(인터뷰·실사 대응) 역할만 둡니다. 내용은 수행계획서 3절(평가 주체)에 있습니다.

## 3. 개인정보 흐름분석

### 3.1 개인정보 처리업무 현황 분석

#### 3.1.1 개인정보 영향도 등급표 작성

안내서 등급표 예시(1등급 5점·2등급 3점·3등급 1점)를 그대로 쓰고, 시스템이 처리하는 개인정보 항목을 등급별로 대응시켰습니다. 여러 등급에 걸치는 항목은 상위 등급으로 봤습니다.

- 산출물: [개인정보 영향도 등급표](개인정보_영향도_등급표.md) (원본 [xlsx](개인정보_처리업무_현황분석.xlsx))

#### 3.1.2 개인정보 처리업무표 작성

개인정보를 처리하는 업무 8개를 도출하고, 업무별 처리 목적·처리 개인정보·주관부서·건수·영향도를 정리했습니다. 영향도는 업무에서 처리하는 항목 중 가장 높은 자산가치이고, 건수는 향후 1년 예상 정보주체 10만 명 기준 추정치(중복 제거)입니다. DB 직접접근은 별도 업무가 아닌 접근 경로로 보고 흐름표·흐름도에 표시합니다.

- 산출물: [개인정보 처리업무표](개인정보_처리업무표.md) (원본 [xlsx](개인정보_처리업무_현황분석.xlsx))

#### 3.1.3 개인정보 처리업무 흐름도 작성

처리업무표의 업무 8개마다 한 장씩, 업무를 수행하는 고객·시스템·부서·연계기관을 레인으로 나눠 그렸습니다. 연계기관(본인확인 서비스·PG·택배사)과 ARGUS는 표시만 하고 내부 처리는 평가하지 않습니다.

- 산출물: [개인정보 처리업무 흐름도](개인정보_처리업무_흐름도.md)

### 3.2 개인정보 흐름표 작성

업무마다 수집, 보유·이용, 제공·파기 단계별로 수집 근거·항목·경로, 보유 형태·암호화 항목·개인정보취급자, 제공 여부·보관 기간·파기 절차·분리보관 여부를 정리했습니다. 코드·DB 확인이 필요한 항목(화면별 조회 항목, 파기 담당, 외부 제공 여부 등)은 시스템 담당자 실사·인터뷰로 확인했습니다. 평가대상 업무 8개를 모두 작성했습니다.

- 산출물: [개인정보 흐름표](개인정보_흐름표.md) (원본 [xlsx](개인정보_흐름표.xlsx))

### 3.3 개인정보 흐름도 작성

흐름표를 바탕으로 안내서 예시 양식(생명주기 × 정보주체·취급자, 처리 흐름, 외부 연계·제공, 처리 개인정보)으로 업무별 개인정보 흐름도를 그리고, 흐름에서 보이는 우려사항과 관련 지표를 표시했습니다. 우려사항은 침해요인 분석에서 확정합니다. 평가대상 업무 8개를 모두 그렸고, 이를 묶어 시스템 전체의 수집·보유·이용·제공·파기 흐름을 한 장으로 보여주는 총괄 개인정보 흐름도를 그렸습니다.

- 산출물: [개인정보 흐름도](개인정보_흐름도.md)

### 4.3 개인정보 침해요인 도출

현황파악에서 미이행·부분이행으로 판정한 33개 지표마다 미흡한 점이 어떤 침해로 이어질 수 있는지 적었습니다. 법적 준거성은 지표의 관련 조항과 과태료·과징금·벌칙을 적고, 법률이 아닌 요건에서 나온 2개 지표(4.1.8·4.8.2)는 법률 외 요건으로 구분했습니다.

- 산출물: [침해요인 목록](침해요인_분석/침해요인_목록.md)

### 4.4 개인정보 위험도 산정

안내서 예시 방식대로 위험도 = 개인정보 영향도 + (발생가능성 × 법적 준거성) × 2로 계산했습니다. 영향도는 침해요인과 직접 관련된 처리업무의 영향도를, 발생가능성은 위반이 지금 일어나고 있는지와 외부에서 바로 닿는 경로가 있는지를 기준으로 정했습니다. 33개 중 최고 점수(14)는 6개입니다.

- 산출물: [위험도 산정결과](침해요인_분석/위험도_산정결과.md)

## 5. 개선계획 수립

### 5.1 개선방안 도출

위험도 산정결과의 33개 침해요인마다 개선방안·수행시기·담당부서를 정했습니다. 수행시기는 위험도 14·12점은 단기(2027.03), 11점은 중기(2027.06), 9점 이하는 장기(2027.12)로 두고, 문서·설정만 바꾸면 되는 항목은 한 단계 앞당겼습니다. 담당부서는 실제로 고치는 부서입니다.

- 산출물: [개선방안 목록](개선계획/개선방안_목록.md)

### 5.2 개선계획 수립

비슷한 개선방안을 개선과제 15개로 묶고 위험도가 높은 과제부터 배열했습니다. 과제마다 안내서 양식(관련 평가항목·법적 요건·과제 상세 내용·담당부서·수행 시기·관련 법령)으로 상세 개선방안을 적고, 필요한 과제에는 개선 후 화면·절차 그림과 근거가 되는 공공 안내서 내용을 붙였습니다.

- 산출물: [개선계획표](개선계획/개선계획표.md), [상세 개선방안](개선계획/상세_개선방안.md)
