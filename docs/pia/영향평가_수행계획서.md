# 데모 커머스 개인정보 영향평가 수행계획서

> 기준 문서: 개인정보보호위원회「개인정보 영향평가 수행안내서」(2025.10)

---

## 1. 평가 목적

데모 커머스(쇼핑몰·백오피스)를 운영 오픈 전 신규 개인정보처리시스템으로 보고, 개인정보의 수집부터 파기까지 처리 과정이 정보주체에게 미치는 영향을 분석해 침해요인과 개선방안을 도출한다. 이미 구현된 시스템이므로, 안내서의 "운영 중 시스템의 보호체계 전반 점검" 유형(13쪽)에 해당한다.

## 2. 평가 대상

| 구분 | 대상 |
|---|---|
| 평가 대상 시스템 | 쇼핑몰(platform-web 고객 화면), 백오피스(관리자 화면), platform-api, platform-db, DB 게이트웨이(db-gateway) |
| 연계 시스템 (흐름도·구조도에 표시, 평가 제외) | ARGUS(접속기록 수집·점검), platform-relay(접속기록 전송), 가상 PG(데모페이, 결제 위탁), 가상 택배(데모택배, 배송 위탁), 가상 본인확인 창(본인확인기관 역할) |
| 대상 정보주체 | 쇼핑몰 회원(고객), 배송지 수령인 |

ARGUS는 접속기록 보관·점검(4.4)의 보호조치 수단으로 증적에 쓰되, ARGUS 내부의 개인정보 처리는 평가하지 않는다. PG·택배는 수탁자 시스템이라 내부 처리는 평가하지 않고, 넘겨주는 항목과 위탁 관리를 평가한다.

## 3. 평가 주체

- 평가 수행: 선구 (1인)
- AI 도구(Claude) 활용: 자료 조사, 코드·문서의 사실 확인, 산출물 초안 정리. 판정·위험도·개선계획은 평가자가 확정한다
- 한계: 시스템 개발자와 평가자가 같아 독립성이 없다(안내서 25쪽은 구축 사업자의 영향평가 수행을 금지). 지정 영향평가기관의 정식 평가가 아니라 안내서 방법론을 따른 자체 평가다

## 4. 평가 기간

| 기간 | 범위 |
|---|---|
| 2026-10-20 ~ 10-22 | ① 수행계획 ~ ④ 침해요인 분석(위험도 산정 포함) |
| ~ 10-23 (여유 시) | ⑤ 개선계획, ⑥ 영향평가서 |
| 이후 | 남은 단계와 이행점검을 이어서 진행 |

## 5. 평가 절차

안내서 수행단계를 따른다: ① 수행계획 → ② 평가자료 수집 → ③ 개인정보 흐름분석 → ④ 침해요인 분석 → ⑤ 개선계획 → ⑥ 영향평가서. 이후 이행단계(개선계획 반영 점검).

사전준비 단계(영향평가 필요성 검토·대가 산정·평가기관 선정)는 자체 평가라 생략한다. 민간 사업자라 영향평가 의무 대상은 아니며(법 제33조제11항, 노력 의무), 자율로 수행한다.

각 단계는 AI 도구로 분석·정리한 논의 자료를 검토해 평가자가 결정한 뒤 진행하고, 결정과 근거를 기록으로 남긴다.

**인터뷰·실사 방법**

| 안내서 방법 | 대체 |
|---|---|
| 담당자 인터뷰 | 평가자가 질문하고 시스템 담당자가 답변(설계서·결정 근거로 보완) |
| 현장·시스템 실사 | 평가자가 요청하고 시스템 담당자가 화면·DB·파일을 직접 확인해 결과와 증적을 제출 |
| 자료 분석 | 개인정보 처리방침 v3, 이용약관 v2, 동의 문안 |

## 6. 주요 평가사항

안내서는 "중점적으로 평가되어야 하는 사항"을 적게 한다(27쪽). 부록 1 양식 예시(411쪽)를 따라 다음을 중점으로 본다.

- 대상 시스템이 개인정보 보호 관련 법적 요건을 만족하는지
- 처리하는 개인정보의 생명주기(수집·보유·이용·제공·위탁·파기)에서 침해 우려가 생길 수 있는지
- 영향평가 항목 점검표 기준으로 주요 침해사항이 있는지

구체적인 중점 항목은 ③ 개인정보 흐름분석에서 근거가 확인된 뒤 이 절에 추가한다.

## 7. 평가기준 및 평가항목

- 평가항목: 안내서의 5개 영역, 28개 분야, 121개 지표(57쪽)
  - **3영역(처리단계별 보호조치)과 4영역(기술적 보호조치)**: 주 평가 대상
  - 1·2영역(관리체계): 시스템으로 판단할 수 있는 범위만 평가
  - 판단할 수 없는 항목은 영역과 관계없이 빼지 않고 **"해당 없음 + 사유"**로 남긴다
- 법령 기준: 안내서를 기준으로 하되, 최신 법령·고시와 충돌하면 차이를 기록하고 해석·적용 기준을 별도로 정한다
- 위험도 산정 방식: ④ 단계에서 안내서·관련 법령과 실제 산정 방법 조사 결과를 바탕으로 정한다

## 8. 자료수집 및 분석계획

| 구분 | 자료 | 위치 |
|---|---|---|
| 외부 정책자료 | 개인정보 보호법(2025.10.2 시행), 시행령(2026.8.20 시행), 안전성 확보조치 기준 고시(2026.7.1 시행)·안내서(2025.11), 표준 개인정보 보호지침(2025.4.11 시행), 전자상거래법 시행령(2026.7.21 시행), 영향평가 수행안내서(2025.10) | 공유 폴더 `knowledge/` |
| 내부 정책자료 | 개인정보 처리방침 v3, 이용약관 v2, 정책정의서(권한·마스킹·보관·파기) | 내부 작업 문서, 설계 문서 |
| 대상시스템 자료 | 요구사항 정의서, 액터별 흐름, 아키텍처 설계서, API 명세서, DB 스키마, 구현 결과·설계 변경 문서, 실행 화면. 소스 코드·DB는 평가자가 직접 보지 않고 담당자 실사로 확인 | 설계 문서 사본, GitHub 저장소 |

세부 목록과 분석 범위는 ② 단계에서 정한다.
